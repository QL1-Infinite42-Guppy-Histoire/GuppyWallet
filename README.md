# GuppyWallet — 42 Chain（Infinite）/ QL1 専用ウォレット

![build](https://github.com/QL1-Infinite42-Guppy-Histoire/GuppyWallet/actions/workflows/build-apk.yml/badge.svg)

42 Chain（旧 Infinite Drivechain）と QL1 の専用ウォレットアプリです。
Android 先行で、React Native + Expo + TypeScript で作っています（iPhone版は後から同じコードで追加予定）。
設計の全体像は [BLUEPRINT.md](./BLUEPRINT.md) を見てください。

> ⚠️ **未監査の開発版です。** 署名・送金機能は実装済みですが、第三者監査は受けていません。
> 実資金で使う場合は自己責任で、必ず少額から試してください。

## 開発状況（2026-11-04 時点）

- **現在版： v0.4.0** — APK は [Releases](https://github.com/QL1-Infinite42-Guppy-Histoire/GuppyWallet/releases) からダウンロード可能
- **ブラウザ拡張機能版：** v0.1.0 を別途リリース（Chrome / Edge、MV3）。アプリと同じ復旧フレーズで同じウォレットが開ける。残高・送受信・Fluke（参加→めくる→確定＝Guide新規発行＋開封演出）まで実装。金庫はパスワード暗号化（PBKDF2+AES-GCM）、鍵はポップアップ表示中のみメモリ保持。配布は Release `ext-v0.1.0` の zip（開発者モードで読み込む）。ソースは `extension/`、ビルドは Actions の Build Extension ワークフロー
- **Guide新規発行：** v0.4.0 — Flukeの確定（settle）で新しいGuideがその場で発行されるように。確定に必要な署名は、公開の乱数ネットワーク drand が自動公開する署名そのものだった（公式フロントのコードから特定し、実在の未確定レコードで eth_call のドライラン成功まで検証済み）。アプリ内で取得・変換して確定まで完結。確定が成功するとオリパ風の開封演出（封入パック→タップで閃光と粒子→実物のGuideカード表示。光り方は実データのティア連動： ティア3以上は虹色、2は金、1は銀青、0は白）が再生される
- **最適化：** v0.3.0 — 機能・見た目はそのままに内部を軽量化。残高取得の二重通信を廃止（ネイティブ残高はトークン取得と同じ回で導出）、更新処理の重なり防止（進行中の取得は共有して1回だけ実行）、価格取得で変わらない情報（ペアアドレス・ペアの token0）をキャッシュして再利用、取引履歴に20秒の短期キャッシュ＋重なり防止、銀河背景の星空を約450個の View から1枚の SVG 描画に変更（見た目は同一）、入金の状態確認ポーリングはアプリが前面にあるときだけ実行（背面では止め、復帰時に即確認）
- **ビルド：** GitHub Actions が標準経路。master へ push するたびに APK がビルドされ、成果物（Artifacts）に上がります（署名は EAS 管理のものと同一＝上書き更新可能）
- **状態：** 主要機能は実装済みでメインネット動作
- **英語対応：** 完了（v0.1.3）。英語に切り替えると、Swap／LP／ステーキング／Bridge／Fluke の各フォームや送金確認画面まで含め、画面の文言がすべて英語になります（v0.1.2 までは一部の画面内部が日本語のままでした）。機能の変更はありません
- **ホーム改善：** v0.1.4 — 「DON'T PANIC」ヘッダーを Orbitron フォントの光る1行表示に小型化（サブ文言を廃止）。取引履歴もホームのチェーン切替（42 Chain / QL1）に連動するよう修正（従来は両チェーン混在表示）。トークン追加はホームから直接入れるようにし、チェーンはホームの選択を引き継ぎ、アドレス入力→チェーンから実情報を読み取って表示→確認してから追加、の2段階に変更
- **UI：** ユーザー提供の「宇宙グッピー」アートは起動スプラッシュ（約3秒＋ Orbitron フォントのロゴ）に採用。v0.1.5 でアートを画面いっぱいに敷く形に変更し、四辺に藍紫のグラデーションのベールを重ねて背景と同化させた（四角い枠は廃止）。v0.1.8 でスプラッシュのズームを修正：全画面 cover では縦長画面で絵が拡大され過ぎて魚の頭が切れていたため、絵全体が見える表示（contain）にし、余白部分は同じ絵を強くぼかして濃い紫の色味を重ねた背景で同化させた（枠なし・同化の良さは維持）。あわせて、ロック解除が成功した瞬間にだけ星が外へ流れる短いワープ演出（約1秒）を追加。銀河背景の色味もアートの藍・紫系に合わせて調整
- **解除方法の選択：** v0.1.6 — 初期設定のときに、ロック解除の方法を「指紋認証」か「アプリのパスワード」か選べるようにした。パスワードはソルト付きハッシュだけを端末に保存し、平文は保存しない。解除はアプリを開くときと送るときだけ（従来どおり）。設定から後で変更も可能で、従来の利用者はそのまま指紋認証として扱われる
- **初回設定と複数ウォレット：** v0.1.7 — 初めて開いたときは「ようこそ → 作成／インポート → 解除方法の選択」の初期設定フローを表示するようになった。設定からは「アカウントを追加」（同じフレーズから次のアドレスを導出）と「ウォレットを追加」（新規作成／別のウォレットの取り込み）ができ、追加したウォレット／アカウントへの切り替えも可能。解除方法はアプリ全体で共通（追加のたびに聞き直さない）。従来の単一ウォレットの保存データは初回起動時に自動で新しい保存形式へ移行され、壊れない
- **入金検知とガス目安：** v0.1.9 — Bridge（BSC/Ethereum → 42 Chain）に、自分のアドレスへの USDT/USDC の入金を検知して知らせるバナー（タップでそのチェーン・通貨の送信フォームへ移動）と、ドル建てのガス目安（BSC $1 / Ethereum $10、実測ガス価格と transferRemote のガス使用量レンジから算出）を追加。ガス用の通貨の残高が目安未満だと、現在のドル換算額つきで理由を表示して送信ボタンを止める。ドル換算が取得できないときは目安チェックを省略し、推測の金額は出さない（最終的なガス代は従来どおり確認画面に表示）
- **他チェーンからの入金：** v0.2.0 — Bridge 画面に「他のチェーンから入金」を追加。ステラ（XLM）を送ると交換サービス（ChangeNOW）を通して BNB になって自分の BSC アドレスに届く、アプリ内フローを実装した（注文作成 → 入金先アドレス＋メモの表示 → 状態の自動追跡）。API キーはアプリに入れず、小さな中継（Cloudflare Workers、`proxy/`）側にだけ置く設計で、この中継の接続が終わるまではアプリ内では「準備中」表示になり注文は作れない
- **入金フローが利用可能に：** v0.2.2 — 中継（Cloudflare Workers）が稼働し、アプリが中継に接続したため、「他のチェーンから入金」が実際に使えるようになった。対応通貨は XLM と SOL（SOL は中継経由の実見積もりで確認してから有効化：1 SOL → 約 0.1315 BNB、最低量は約 0.00525 SOL）。届いた BNB から先は v0.2.1 の「一つの流れ」で 42 Chain の USDT まで進める。次は少額の実送金テストで、目減りと所要時間を実測する
- **入金注文の期限ガード：** v0.2.3 — 入金待ちのまま24時間（注文作成から）過ぎた注文は、送金先アドレスとメモを表示・コピーできなくなり、「期限切れ」表示と新しい入金ボタンに切り替わる（期限切れアドレスへの誤送金防止）。期限内は残り時間を表示。すでに入金が進んだ注文には影響しない
- **一つの流れで 42 Chain まで：** v0.2.1 — BSC に届いた BNB から先を、一つのガイド付きの流れにした。入金の完了画面、または Bridge 画面の BNB 検知バナーから「42 Chainまで進める」を押すと、4段階の進み具合（BNBが届いた → USDTに替える → 42 Chainへ送る → 完了）を見ながら進める。ガス代分（目安 $3、届いた量が少ないときは $1.50、それ以下なら全部をガス代として残して正直に止まる）を自動で残して PancakeSwap V2 で USDT に替え（BSC の USDT は 18 桁であることをオンチェーンで確認済み）、そのまま既存のブリッジで自分の 42 Chain アドレスへ送る。交換とブリッジはそれぞれ確認画面＋認証つきの署名で、自動では実行しない。ブリッジの途中で閉じても、場所は端末に残り、次回はブリッジの段階から再開できる
- **残タスク：** MT 回答待ち4件（下記セクション）と、既知の制約の解消

## できること（実装済み・メインネットで動作）

- ウォレット作成／インポート（BIP-39 24語、鍵は端末の SecureStore 内のみ）。初回は初期設定フローで作成／取り込みし、解除方法（指紋認証／パスワード）を選択。複数のウォレットとアカウントの追加・切り替えに対応
- 残高表示：42 Chain / QL1 の切替表示、円・ドル換算の合計、取引履歴
- 送金／受取（QRコード表示・読み取り対応）
- Swap / LP：42 Chain は Don't Panic（Nutri-Matic V2）、QL1 は QomSwap で実際に交換・流動性提供が可能
- ステーキング：42 Chain のプリコンパイル経由で委任・解除・報酬請求。st42（流動性ステーキング）も対応
- Bridge：42 Chain → QL1 / Ethereum / BSC、および BSC / Ethereum → 42 Chain（Hyperlane 方式）
- NFT / The Guide / Starlight（Guide登録と報酬請求）、Fluke（参加・めくる）
- QNS（.qom）は保有ドメインの表示のみ（新規登録はサービス側で終了）
- 日本語／英語の切替、銀河×ガラスの UI

## MT 受領待ち項目の現状（2026-11-01 更新）

当初リストアップしていた確認事項は、**ほとんどが MT の返信を待たずに解決しました**
（オンチェーン検証と公式サイトのフロントコード解析による）。全量は BLUEPRINT.md §5。

解決済み：コントラクトアドレス一覧と ABI、公式 RPC の要否、QL1 の Cosmos Chain ID・
最小単位（aqom）・decimals、ステーキング方式、価格／quote の取得方法（DEX のプール残高から算出）。

**実際にまだ MT の回答待ちなのは、次の4件だけです：**

- Fluke の精算（settle）に必要な署名の発行方法（公式 API が現在署名を配っていない）
- QL1 → 42 Chain ブリッジの実配送が稼働しているかの確認（公式統計で QL1 発の配送が 0 件のため、アプリ側は QL1 発の送信を止めています）
- QL1 での ZAP の交換ルート（QomSwap に直接ペアが無い）
- テストネット／テストトークンの有無

## 既知の制約（正直に）

- 価格は DEX プールの残高から算出する目安です。流動性の薄いトークンでは大きくずれることがあり、信頼できない価格のトークンは合計から除外しています
- Fluke の精算（settle）は公式の署名が得られた場合のみ実行できます（上記 MT 待ち項目）
- Android の package id は `one.zaphod.wallet.prototype`（プレースホルダー）です。ストア公開前に正式な ID を決めます

## 動かし方

```bash
npm install
npx expo start        # または: npm start
```

- 型チェック：`npm run typecheck`（`tsc --noEmit`）
- APK ビルド：**GitHub Actions**（`.github/workflows/build-apk.yml`）が標準です。
  master への push、または Actions 画面からの手動実行（workflow_dispatch）で、
  ランナー上で EAS のローカルビルド（preview プロファイル）を実行し、
  APK が artifact「guppy-wallet-apk」として保存されます。
  署名は EAS 管理のキーストアのまま（`EXPO_TOKEN` は GitHub Secrets で管理）。
- フォールバックとして、従来どおり EAS クラウドでのビルドも使えます：

```bash
eas build -p android --profile preview
```
